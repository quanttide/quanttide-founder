# 记忆分层校验

一份内容只有一个正确去处。放错层的代价不是难看，是下一轮没人找得到它，或者它躺在那里被当成新发现重写一遍。

这个单元自带判层所需的全部材料，不依赖当次对话。用法三步：取出原句；逐层过「语义界线」；按该层形状改写。

## 结构

| 层 | 文件 | 一行写什么 | 一句话判 |
|---|---|---|---|
| journal | `<集>/journal/YYYY-MM-DD.md` | 发生过什么，原样记录 | 抽掉日期还成立吗 |
| insight | `<集>/insight/<主题>.md` | 一句能被后来的事推翻的机制 | 推翻后要改做法吗 |
| roadmap | `data/roadmap/<主题>/<主题>.md` | 先做什么，后做什么 | 回答下一步干什么吗 |
| profile | `data/profile/<分区>/` | 我反复怎么判断 | 换一件事还成立吗 |
| intention | `<集>/intention/<主题>.md` | 要什么、不要什么的原话 | 是现场澄清还是结论 |

## 语义界线

界线只写在相邻两层之间，跨层的不用管。

**journal 与 insight**：前者记事件，后者记机制。事件抽掉日期与当事人就没了；机制抽掉之后还在。

「今天让 AI 写路线图，第一版太长，砍了一轮」是事件。「初稿必冗余，精简要写进流程」是机制，哪天模型不再冗余，这条就该废掉。

**insight 与 roadmap**：前者说世界怎么运转，后者说我去做什么。带「先做」「应该」「不做」的是选择，不是认识。

一条内容同时有两者时，认识留在 insight，动作归 roadmap，两处各写一句，不互相复制。

**insight 与 profile**：前者是一句能被推翻的话，后者是一套反复出现的判断方式。推翻成本低、一次事件就能证伪的，写进 insight；跨事稳定、改起来要动整个人的，写进 profile。

「我倾向于先搭框架再填内容」是特征。「结构先行时填充更快」是洞察。

**roadmap 内部**：已决策要有行动佐证，没有行动的只能挂待决策。提议不等于决定，说过一次不等于定了。

**intention 与其余**：intention 收的是人机对齐的现场要求，原话优先，不做提炼。提炼过的就不是意图，是结论。

## 正反例

例子取自本仓真实内容，成对给出：同一段原话，写成什么样该收，写成什么样不该收。

**例一，机制与事件**

- 收进 insight：初稿必冗余，因为遗漏可见、冗余不可见；把「生成后强制砍一轮」固化成默认一步，冗余就从每次判断变成固定动作。
- 留在 journal：今天让 AI 写东西，第一版又长又散，砍了一轮才好。

理由：后者去掉日期就空了。

**例二，认识与动作**

- 收进 insight：约束生成很难，约束验收容易；生成难控，检查好做。
- 收进 roadmap：先做存量巡检，用数出来的量决定闸门要不要装。

理由：前者描述落差，后者排先后。

**例三，可推翻与不可推翻**

- 不收：整个系统开始观察自己，形成自指闭环。

理由：推不翻，推翻之后也不改任何做法。这类话适合写进论文，不适合进 insight。

**例四，特征与洞察**

- 收进 profile：我反复从具体例子倒推框架，而不是先立框架再找例子。
- 收进 insight：AI 学的是词与词的相邻，不学词与读者的关系；它写小说时会调入工程术语。

理由：前者是习惯，后者是机制，后者能被一次反例推翻。

**例五，提议与决策**

- 待决策：写入处要不要加一道校验，还没定。
- 已决策：先巡检后闸门，巡检用来决定闸门装不装。

理由：后者有行动与顺序，前者只有问句。

## 自检

写完一处，逐条过：

1. 抽掉日期、人名、项目名，这句还成立吗？不成立，退回 journal。
2. 它回答「下一步干什么」吗？是，归 roadmap，再看有没有行动佐证。
3. 它讲的是「我反复怎么判断」吗？是，归 profile。
4. 后来的事能推翻它吗？推翻之后做法会变吗？两个都否，不收。
5. 这层已经有同一句了吗？有，就地改写或留互链，不另起一条。

## 常见误判

- 把提议写成已决策：说了「应该」，没有行动，仍是待决策。
- 把动作混进洞察：句子以「要」「应该」开头，先看它是否其实归 roadmap。
- 把单次事件拔高成机制：一次出错只说一次，同一机制反复出现才写进 insight。
- 一层内容抄到三层：同一认识只在一处展开，其余留一句互链。
