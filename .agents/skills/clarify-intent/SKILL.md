# 澄清意图

把一句「不对劲」变成一条记录和一段能粘回对话的话，同一类差重复出现时提示立成规则。命令是 `qtfounder-lab`（与正式版 `qtfounder` 区分），契约见 lab 仓 `src/cli/docs/api-references/`。

## 澄清的形状

澄清长得像一个改字请求，不是一个问卷。**永远先把候选写出来让用户改，不空手问问题。**

开口就三行加一句问：

```text
原以为：只改我指定的那一段
实际：整段重写
差：它不知道「指定」是排他的
要不要记？
```

用户要做的动作只有一个：回「对」，或改其中一行。不要求他重新陈述背景，不问「你具体想怎样」这类空问题——三行是从他的原话里摘的，摘不准是 agent 的错，他改一个字也算。

**记完只回一行**：`已记 int_xxx / clr_xxx，这次是第 N 次` + 那段可直接粘回的话。不复述流程、不解释设计。

## 规则

- **三级触发，由轻到重**：A 过程中主动点破（只提示、不写库）→ B 收尾主动复盘（每次任务只提一次）→ C 用户召唤先定位对象再两问。
- **主动但节流**。同一类差一次会话只提一次；用户说「不用记」则该会话不再提这一类；提示只有一句，不解释、不展开、不打断手头的活。
- **主动触发只认明确信号，不做情绪检测**。没有信号就不出声；不猜、不劝、不复盘用户的心情。
- **产出场景不打断**。用户在写分析、写文档、推方案时那是在产出，不是返工——不在这种时候插澄清。只在「他说的和做的对不上」且确实想改时开口。
- **只清一件事**。一次一条 `actual`，不打包；两处不对劲就记两条，第二条等第一条确认完再提。
- **判断都在 agent 侧**：把「它就是不行」翻译成具体行为、判断两行是不是同一条差、决定挂在哪件事下，都是 agent 的活，用户只点头或改字。
- **写库只有两条路**：用户点头回应提示；或用户已经在消息里把「原以为 / 实际做了什么」说清楚（此时直接记一条并回执，不再追问）。其余一律不写。
- **记歪了用 `--revise <clr_id>` 原地改**，重拼提示词、不新增记录；不要手改账本文件（手改最容易漏掉提示词那一份，账本就不自洽了）。删整条才手改文件。
- **规则文本永远是用户的话**。工具与 agent 都不代写规则，只把候选顶到用户面前，点头后才落库。
- **数据目录固定，不按 cwd 散落**。所有命令前先 `export QTFOUNDER_LAB_DATA=${QTFOUNDER_LAB_DATA:-$HOME/.local/share/qtfounder-lab}`——CLI 默认落 `./data/`，换目录跑就会各存一份。
- 输出给用户的是提示词原文（`prompt` 字段），不让用户自己组织语言。

## 工作流

### A · 过程中主动点破（不写库）

命中任一信号就点破一句：

- 同一个要求用户说了第二遍；
- 用户话里出现「又是这样 / 我又说了一遍 / 不是这个意思 / 别再」；
- 同一处产出被连改三次；
- agent 自己发现同类错误在本会话重复（又铺陈、又漏验收）。

按「澄清的形状」给三行 + 一句问。用户点头 → 记一条；用户说不用 → 本会话不再提这一类。**这一级不写库。**

### B · 收尾主动复盘（每次任务只提一次）

任务交付时跑一次：

```bash
qtfounder-lab work intent --json
```

当前 intent 的 `candidates` 里有 `count ≥ 2` 的项，就问一句「这类差第 N 次了，要不要立规则？你给一句话」。**等用户给文本**，不替它写；同时把 `rules.md` 提醒一句：下次开工前给 AI 看。

### C · 用户召唤（`/clarify-intent`）

召唤不等于「已有对象」。按顺序：

1. **先定位对象**：哪句话、哪个动作、哪次返工。能从上下文认出来，就直接按「澄清的形状」写出三行让用户改。
2. **定位不到就问一句**：「要澄清哪一段？」——只问这一句，不上两问。
3. **对象明确但两行还不清**，再问：你原本以为它知道 / 会做什么？它实际做了什么？两问必须落到具体行为，答得笼统（「它就是不行」）追问一次「举它刚才那句话或那个动作」。追问后仍笼统，就记用户实际说的那句，不替他编。

### 记一条，拿回提示词

一次把整条记录走 stdin，`--json` 拿结构化结果：

```bash
qtfounder-lab work clarify --stdin --json <<'JSON'
{"before":"我以为它知道我要能直接跑的代码","actual":"给了五段解释加伪代码"}
JSON
```

`prompt` 可省略，省略时按两问拼模板；要新开一件事加 `"task":"<一句话>"`，不加就挂到最近一件事上。把返回的 `prompt` 原文给用户，并说明「可以直接粘回对话」。`deduplicated` 为 true 说明这条之前记过，只提示、不重复记账。

### 用户点头才落规则

```bash
qtfounder-lab work clarify --rule "<用户原话>"
```

落库后回一句：写进了哪个文件、这一批重复差已标为处理过。`rules.md` 由用户自己保管。

## 示例

```text
（A 级：用户第三次要求同一处改动）
agent：原以为：只改我指定的那一段
       实际：整段重写
       差：它不知道「指定」是排他的
       要不要记？
用户：对

agent：（跑 clarify --stdin）
       我原以为「只改我指定的那一段」。
       它实际做了「整段重写」。
       请按我原以为的重做一遍，把这两条当约束。
       —— 已记 int_1SC3 / clr_X8BG，这段可以直接粘回对话。

（B 级：任务交付时）
agent：（跑 intent --json，同类差 ×2）
       这类差第 2 次了，要不要立成一条规则？你给一句话。
用户：只改指定段，别动其它
agent：（跑 clarify --rule "只改指定段，别动其它"）已写进 rules.md，下次开工前给它看。

（C 级：召唤但没有对象）
用户：/clarify-intent
agent：要澄清哪一段？
```

## 排错

错误一律是 JSON、写在 stderr，退出码三档：

| 码 | 含义 | 常见原因 |
|----|------|---------|
| 0 | 成功（含去重） | — |
| 2 | 用法错 | `--stdin` 少 `before`/`actual`；`--task` 与 `--rule` 同给；`--rule` 文本为空；无可挂的意图（没给 `task` 而库里还没有任何意图） |
| 3 | 未找到 | `--id` 指向的意图不存在 |
