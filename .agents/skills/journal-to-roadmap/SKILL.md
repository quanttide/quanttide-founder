# 日志到路线图

把 `<集>/journal/` 中的混合日志蒸馏为**同一集** `data/roadmap/<集>/` 下的主题路线图。roadmap 是方向层，写法是散文：开头一段说当前先解决什么、先后顺序如何，之后按交付物分节（案例、平台等）。

## 三问过滤

| 问题 | 去向 |
|------|------|
| 这是"要做什么 / 选什么 / 在问什么"？ | `data/roadmap/<集>/` |
| 这是"发生了什么"？ | 留在 `<集>/journal/` |
| 这是"我是什么样的人"？ | `<集>/profile/` |

三问都答不上的（单次一闪念、无行动、无后续）不收。

## 证据分级

- 多日重复或已有行动 = **已决策**
- 单次提及、无行动 = **待决策候选**
- 反复出现且未解 = **核心问题**
- 日志中标注的长期主题 = **元目标**（写作时归入「目标」节的 `### 元目标` 子层，不设顶级节）

## 原则

- **单位是决策线索，不是日期文件**，多对多。
- **以最新状态为准**：决策会翻转（想过后决定"不动"），跨日合并、就地改写；演变史是 journal 的职责，roadmap 只反映当前状态。
- **与 profile 分工不复制**：profile 收"怎么判断"（价值观、思维框架），roadmap 收"判断出了什么"（选择、目标）。同一内容两处出现时写法必须不同，或一方只留互链。
- **不收**：事件、情绪、业务状态、应对策略——分别留在 journal 或归 profile。

## 流程

1. **扫描**：通读本记忆集的全部日志——`<集>/journal/` 全部，加上集根的当天日志（即集根的 `YYYY-MM-DD.md`），按方向类关键词定位候选：决定、决定不、先做、优先、不动、交给、合并、拆开、待定、需要考虑、还没定、怎么找、问题是、主题：。不读其他记忆集的日志。
2. **过滤**：三问过滤 + 证据分级，拿不准的降级处理（已决策 → 待决策）。
3. **聚类**：同一决策/问题跨日期合并为一条，按主题归入路线图文件。
4. **合并**：读现有 `data/roadmap/<集>/` 文件，新线索增条目，已有条目按最新状态改写，被翻转的决策直接替换，过时的移除。

## 输出

`data/roadmap/<集>/` 按主题分文件，主题名与同集其他层对齐，延续主题命名法，不用日期。文件内先一段散文说当前与顺序，再按交付物分节：

```markdown
# 主题名

当前先解决……，以……作为首个落地场景；在此基础上再确定……的顺序。

## 案例

这一节该产出什么。

## 平台
```

不设「目标 / 核心问题 / 已决策 / 待决策」固定节——那套格式已废弃。节名取交付物本身，节内写该交付物要产出什么；尚未想清的节留空标题。

条目一行一条，祈使句或陈述句，必要时括注依据或约束。

## 边界

- **当前与顺序一节必须写清先做什么、后做什么**，并给出为什么是这个顺序；写不出顺序，说明方向还没收敛，退回 journal 再攒线索。
- **按交付物分节**：节名用交付物的名字，不用方法词；一节只写一件要产出的东西。
- 元目标跨主题时不重复收录，放最贴切的一个主题文件。
- roadmap 不记录决策是怎么来的，只记录决策是什么。
