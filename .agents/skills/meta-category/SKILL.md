# 元类别

一份内容只有一个正确去处。放错格的代价不是难看，是下一轮没人找得到它，或者它躺在那里被当成新发现重写一遍。

标准资产共十八种，组成两个九宫格。Context 与 Archive 不占格：前者是所有格子的默认入口，后者是过时资产的出口。

## 陈述型：时间 × 类型

回答组织「知道什么」。时间维度看契约走到哪一步，类型维度看这条内容本身是什么。

- 过去是已履行的契约，现在是正在履行的契约，未来是将要履行的契约。
- 事件类记行动与计划，语义类沉淀认知与参考，自我类呈现身份与叙事。

| 时间 | 事件类 | 语义类 | 自我类 |
|---|---|---|---|
| 过去 | Report 报告 `data/report/` | Library 图书馆 `data/library/` | History 历史 `data/history/` |
| 现在 | Journal 日志 `data/journal/` | Profile 档案 `data/profile/` | Brochure 宣传册 `data/brochure/` |
| 未来 | Roadmap 路线图 `data/roadmap/` | Insight 洞察 `data/insight/` | Intention 愿景 `data/intention/` |

## 程序型：约束力 × 消费对象

回答组织「怎么做事」。约束力看它管到多深，消费对象看它写给谁用。

- 宪法是最高约束，定基本原则与权责划分；法律是中等约束，写成系统性程序；法理约束最低，讲原理与方法论。
- 三列依次面向人读、AI 解析与直接运行。

| 约束力 | 规则 | 建模 | 应用 |
|---|---|---|---|
| 宪法 | Bylaw 章程 `docs/bylaw/` | Specification 工程标准 `docs/specification/` | Toolkit 标准库 `packages/` |
| 法律 | Handbook 手册 `docs/handbook/` | Gallery 案例 `docs/gallery/` | Platform 平台 `apps/` |
| 法理 | Tutorial 教程 `docs/tutorial/` | Essay 论文 `docs/essay/` | Laboratory 实验室 `examples/` |

## 手册与案例

两格同处法律层，约束力相当，最容易混。分界不在题材，在粒度。

手册收一类情况的判断，是换一个实例仍然成立的尺子。案例收一次具体工作，装着那次的时间、参与人与做法结果。

同一份内容，换一个实例还成立，归手册；只对那一次成立，离开那次就散架，归案例。两边不并存：提炼出的尺子进手册，那次的过程与结果进案例。

## 入口与出口

Context 是默认入口。日常里先感知到模式或疑问，记进 `data/context/`，再从那里分诊。一时分不清的也先放这里，等它重复。

Archive 是出口。整份过时的资产移进 `data/archive/`，留一份可追溯的底，不就地删。

## 准入

先定格，再看够不够格。

**规格**：这个概念进了体系吗。定义稳定、边界清楚、对错判得出来，才够格。还在推演、阈值靠估的，先进论文，等它被验证再升格。

**章程**：涉及授权与权责划分吗。只管什么算对、不涉及谁的，是规格。

**手册与案例**：换一个实例还成立吗。成立进手册，不成立进案例。

**论文**：还在解释吗。同一主题已经有规格的，论文只写解释、举例与例外，不重复条文。

## 分诊

日志是各格共同的源头。日志新增或修改后，一次通读，分到各自该去的格，不必为每一格各跑一遍。

### 分到哪一格

- 这是「发生了什么」，留在 Journal，不动。
- 这是「我想通了：X 其实是因为 Y」，归 Insight。
- 这是「我要做什么、先做什么」，归 Roadmap。
- 这是「我到底想要什么，要 X 不要 Y」，归 Intention。
- 这是「我反复怎么判断」，归 Profile。

一句都套不上的（单次一闪念、无行动、无后续）不收。

### 分级

同一内容照凭证强弱分档，弱的一律降级，不往强里写。

Insight 分两档：多日重复或有验证、有行动的，标已确认；单次想通、未验证的，标假说。

Roadmap 分四档。多日重复或已有行动的算已决策；单次提及且没有行动的算待决策候选。反复出现且未解的记为核心问题；日志里标注的长期主题记为元目标。

Intention 不分档，收原话。原话本身就是要对齐的东西。

### 四步

1. 扫描：通读本集全部日志，加集根当天日志；不读其他集。候选词分三类，认知类如发现、其实、规律、核心点，方向类如决定、先做、待定、问题是，意图类如要、不要、应该、澄清。
2. 分诊：按上表定格，按凭证定档。拿不准的降一档，或退回 Journal 再攒线索。
3. 聚类：同一机制、同一决策、同一意图跨日期合并，按主题归文件。被推翻的就地改写或移除，其余格只反映当前状态。
4. 合并：先读目标格已有文件，再读同集其他格，防止写两处。重复的留互链，过时的删。

### 原则

- 单位是线索，不是日期文件，一条线索可以跳很多天。
- 以最新为准：决策与澄清会翻转，想清楚之后决定「不动」也是一种状态。
- 分工不复制：同一内容只在一处完整展开，其余格写不同侧面或一句互链。
- 晋升与降级：反复套用、稳定成思维框架的，并入 Profile，原处改写为互链；它引出选择后，选择归 Roadmap。
- 只记是什么，不记怎么来的：Roadmap 不写决策过程，Insight 不展开发现经过。
- Intention 写给 AI 读：祈使或明确陈述，一条意图加一句背景。仅在已设 `intention/` 的记忆集里运行。

## 各格的写法

### Insight

按主题分文件，主题名与同集其他格对齐，不用日期。文件内两节，空节省略：

```markdown
# 主题名

## 已确认

- **一句话**：机制一句话。出处：事件简述（日期）。

## 假说

- **一句话**：机制一句话。出处：事件简述（日期）。
```

写成陈述句（「X 导致 Y」），不写「我觉得可能」；出处一句带日期，不展开叙事。只陈述认识，不给建议，也不写「所以要做什么」。

### Roadmap

按主题分文件，主题名与同集其他格对齐，不用日期。文件内先一段散文说当前先解决什么、先后顺序如何，再按交付物分节：

```markdown
# 主题名

当前先解决……，以……作为首个落地场景；在此基础上再确定……的顺序。

## 案例

这一节该产出什么。

## 平台
```

不设「目标 / 核心问题 / 已决策 / 待决策」固定节，那套格式已废弃。节名取交付物本身，不用方法词；一节只写一个交付物，尚未想清的节留空标题。

节内一行一条，祈使句或陈述句，必要时括注约束。**做完一节就删一节**：近景只有一份当前版，做完的留在上面，下一轮读的人会以为还要做；变更记进该仓的 `CHANGELOG`。

写不出先后顺序，说明方向还没收敛，退回 Journal 再攒线索。

### Intention

按主题分文件，主题集与同集 Insight、Roadmap 对齐。日志里没有内容的主题不建文件。一条一行：

```markdown
# 主题名

- **意图**：要 X，不要 Y。背景：摩擦或提问一句（YYYY-MM-DD）。
```

改写时守住四条：指令在日志里有原话；压缩时保留改变含义的约束（范围、数量、例外）；看似冲突的几条写清解耦条件；与 Insight、Roadmap 实质重复的不收。

## 语义界线

界线只写相邻两格之间，隔格的不写。

**Report 与 Journal**：前者收已履行完毕的一轮工作，后者收正在发生的当天。判句是「这件事结束了没有」。

**Journal 与 Insight**：前者记事件，后者记机制。事件抽掉日期与当事人就没了；机制抽掉之后还在。

**Insight 与 Roadmap**：前者说世界怎么运转，后者说我去做什么。带「先做」「应该」「不做」的是选择，不是认识。两者并存时，认识留 Insight，动作归 Roadmap，各写一句。

**Insight 与 Profile**：前者是一句能被推翻的话，后者是一套反复出现的判断方式。一次事件就能证伪的进 Insight；跨事稳定、改起来要动整个人的进 Profile。

**Intention 与 Profile**：前者是「我要什么」，后者是「我是什么样的人」。要什么会随事变，是什么样的人不随事变。

**Insight 与 Intention**：同一条内容，Insight 写成能对错的机制，Intention 写成给 AI 的指令。已经成了决策、指令不再多说什么的，以 Roadmap 为准，Intention 不重复收。

**Roadmap 内部**：已决策要有行动跟着，没有行动的只能挂待决策。提议不等于决定。

**章程与规格**：同处宪法层。章程管权责划分与执行，规格管对错标准。一条规定要人签字放行才生效的，是章程。

**规格与论文**：同属建模列，约束力一头最高、一头最低。规格是可执行的硬约束，论文是方法论解释。同一主题两处展开，就是两份会各自过时的复制件，跨格只留互链。

## 正反例

取自真实发生过的事，成对给出。

**例一，机制与事件**

- 收进 Insight：初稿必冗余，因为遗漏可见、冗余不可见；把「生成后强制砍一轮」固化成默认一步，冗余就从每次判断变成固定动作。
- 留在 Journal：今天让 AI 写东西，第一版又长又散，砍了一轮才好。

理由：后者去掉日期就空了。

**例二，认识与动作**

- 收进 Insight：约束生成很难，约束验收容易；生成难控，检查好做。
- 收进 Roadmap：先做存量巡检，用数出来的量决定闸门要不要装。

理由：前者描述落差，后者排先后。

**例三，可推翻与不可推翻**

- 不收：整个系统开始观察自己，形成自指闭环。

理由：推不翻，推翻之后也不改任何做法。这类话适合写进论文，不进 Insight。

**例四，规格与论文**

- 只够进论文：治理成本的三项与净收益公式，写完被否决，降为论文里的一节。
- 够格进规格：语境由语场、语旨、语式三项构成，每项能分别求值。

理由：前一例给不出数据支撑的阈值，权重靠估；后一例定义稳定、边界清楚。

**例五，手册与案例**

- 进手册：一次写入前要过哪几道检查，换成别的写入仍然成立。
- 进案例：某天把校验单元改写成结构、语义、正反例三段，花了多久，遇到什么。

理由：前者是可复用的尺子，后者只对那次成立。

**例六，做完的那条**

- 近景只留未完成的：某节做完，从主题文件里删掉，变更记进 `CHANGELOG`。
- 不留在近景：做完的继续挂着，下一轮读的人会以为还要做。

理由：近景只有一份当前版，写完的那份就是历史。

## 自检

写完一处，逐条过：

1. 先问两域：这是陈述组织知道什么，还是规定怎么做事。
2. 陈述型先定时间：说的是过去、现在还是未来。
3. 再定类型：事件、语义，还是自我。
4. 程序型先定约束力：是权责、是程序，还是方法论。
5. 抽掉日期、人名、项目名，这句还成立吗？不成立，退回 Journal。
6. 它回答「下一步干什么」吗？是，归 Roadmap，再看有没有行动跟着。
7. 它讲的是「我反复怎么判断」吗？是，归 Profile。
8. 它是「要 X 不要 Y」的原话吗？是，归 Intention，原样收。
9. 后来的事能推翻它吗？推翻之后做法会变吗？两个都否，不收。
10. 要进规格，概念入体系了吗？阈值有出处吗？没有，先进论文。
11. 换一个实例还成立吗？成立进手册，不成立进案例。
12. 这一处已经有同一句了吗？有，就地改写或留互链，不另起一条。

## 常见误判

- 把推演当标准：没有数据支撑的阈值，只能进论文，等验证过再升格。
- 把提议写成已决策：说了「应该」，没有行动，仍是待决策。
- 把动作混进洞察：句子以「要」「应该」开头，先看它是否其实归 Roadmap。
- 把单次事件拔高成机制：一次出错只说一次，同一机制反复出现才写进 Insight。
- 把提炼过的结论当意图：Intention 收原话，提炼过的归 Insight 或 Roadmap。
- 手册写成案例：写成了那一次的过程，换一个实例就作废，尺子没留下来。
- 案例写成手册：只留下结论，过程与参与人丢了，下次没人知道它从哪来。
- 约束力错位：该硬的标准写成方法论，或该讲原理的写成硬条文。
- 写完不撤：近景只有一份当前版，做完的要从主题文件里删掉。
- 一类内容抄到多格：同一内容只在一处展开，其余留一句互链。
- 日志里没有的不编造：拿不准就不收，留在日志里等它重复。
