# 元类别

一份内容只有一个正确去处。放错类的代价不是难看，是下一轮没人找得到它，或者它躺在那里被当成新发现重写一遍。

## 两域分界

`data/` 是陈述型：记录世界是什么样。`docs/` 是程序型：规定怎么做事。分界先判，再看下一层。

## 记忆类

| 类 | 位置 | 一行写什么 | 一句话判 |
|---|---|---|---|
| journal | `<集>/journal/YYYY-MM-DD.md` | 发生过什么，原样记录 | 抽掉日期还成立吗 |
| insight | `<集>/insight/<主题>.md` | 一句能被后来的事推翻的机制 | 推翻后要改做法吗 |
| roadmap | `data/roadmap/<集>/` | 先做什么，后做什么 | 回答下一步干什么吗 |
| profile | `data/profile/<分区>/` | 我反复怎么判断 | 换一件事还成立吗 |
| intention | `<集>/intention/<主题>.md` | 要什么、不要什么的原话 | 是现场澄清还是结论 |

## 文档类

| 类 | 位置 | 回答什么 | 一句话判 |
|---|---|---|---|
| 章程 | `docs/bylaw/` | 谁被授权做什么，违反怎么办 | 规定的是权责吗 |
| 规格 | `docs/specification/` | 必须满足什么才算对 | 概念已入体系吗 |
| 手册 | `docs/handbook/` | 具体怎样做 | 能照着一步步做吗 |
| 案例 | `docs/gallery/` | 遇到过什么、当时怎么处理 | 先有故事后有标准吗 |
| 论文 | `docs/essay/` | 为什么这样成立 | 还在解释，没有定论吗 |
| 教程 | `docs/tutorial/` | 后来的人怎么学会 | 读者是从零开始吗 |

标准写成机器能跑的形式，落工具契约，不另立散文。

## 准入

进哪一类之前，先过对应的一问。答不上就不进这一类。

**规格**：这个概念进了体系吗。定义稳定、边界清楚、对错判得出来，才够格。还在推演、阈值靠估的，先进论文，等它被验证再升格。

**章程**：涉及授权与权责吗。章程规定谁可以做、谁必须做、越界怎么办。只讲什么算对、不涉及谁的，是规格。

**手册**：是步骤吗。一条一条照着做能复现的，是手册；讲为什么成立的，是论文。

**案例**：是先有故事吗。标准从已有案例归纳出来，放案例集；凭推演先立标准，放规格或论文。

**论文**：还在解释吗。同一主题已经有规格的，论文只写解释、举例与例外，不重复条文。

## 分诊

日志是四层共同的源头。日志新增或修改后，一次通读，分到各自该去的层，不必为每一层各跑一遍。

### 分到哪一层

| 问句 | 去向 |
|---|---|
| 这是「发生了什么」？ | 留在 `<集>/journal/`，不动 |
| 这是「我想通了：X 其实是因为 Y」？ | `<集>/insight/` |
| 这是「我要做什么、先做什么」？ | `data/roadmap/<集>/` |
| 这是「我到底想要什么，要 X 不要 Y」？ | `<集>/intention/` |
| 这是「我反复怎么判断」？ | `data/profile/` |

一句都套不上的（单次一闪念、无行动、无后续）不收。

### 分级

同一内容照着凭证强弱分档，弱的一律降级，不往强里写。

- insight：多日重复或有验证、有行动，标**已确认**；单次想通、未验证，标**假说**。
- roadmap：多日重复或已有行动，算**已决策**；单次提及、没有行动，算**待决策候选**；反复出现且未解，记为**核心问题**；日志里标注的长期主题，记为**元目标**。
- intention：不分档，收原话。原话本身就是要对齐的东西。

### 四步

1. **扫描**：通读本记忆集的全部日志——`<集>/journal/` 全部，加上集根的当天日志。不读其他记忆集的日志。按三类词定位候选。认知类：发现、意识到、原来、其实、关键是、临界点、原因在于、规律、核心点。方向类：决定、先做、优先、不动、交给、合并、拆开、待定、还没定、问题是、主题。意图类：要、不要、别、希望、应该、必须、只、统一、澄清、不对、不是这个、执行者、掌控、验收、约束。
2. **分诊**：按上表定层，按凭证定档。拿不准的降一档，或退回 journal 再攒线索。
3. **聚类**：同一机制、同一决策、同一意图跨日期合并为一条，按主题归文件。以最新状态为准，被推翻的就地改写或移除；演变经过是 journal 的事，其余层只反映当前状态。
4. **合并**：先读目标层已有文件，再读同集其他层，防止同一内容写两处。已有的就地改写，重复的留互链，过时的删。

### 原则

- **单位是线索，不是日期文件**，一条线索可以跨很多天。
- **以最新为准**：决策与澄清会翻转，想清楚之后决定「不动」也是一种状态。
- **分工不复制**：同一内容只在一处完整展开，其余层写不同侧面或一句互链。
- **晋升与降级**：一句话反复套用、稳定成思维框架，并入 `data/profile/`，原处改写为互链；它引出选择后，选择归 roadmap，只留那一句。
- **只记是什么，不记怎么来的**：roadmap 不写决策过程，insight 不展开发现经过。
- **intention 写给 AI 读**：祈使或明确陈述，一条意图加一句背景。仅在已设 `intention/` 的记忆集里运行。

## 各层的写法

### insight

按主题分文件，主题名与同集其他层对齐，不用日期。文件内两节，空节省略：

```markdown
# 主题名

## 已确认

- **一句话**：机制一句话。出处：事件简述（日期）。

## 假说

- **一句话**：机制一句话。出处：事件简述（日期）。
```

写成陈述句（「X 导致 Y」），不写「我觉得可能」；出处一句带日期，不展开叙事。只陈述认识，不给建议，也不写「所以要做什么」。

### roadmap

按主题分文件，主题名与同集其他层对齐，不用日期。文件内先一段散文说当前先解决什么、先后顺序如何，再按交付物分节：

```markdown
# 主题名

当前先解决……，以……作为首个落地场景；在此基础上再确定……的顺序。

## 案例

这一节该产出什么。

## 平台
```

不设「目标 / 核心问题 / 已决策 / 待决策」固定节，那套格式已废弃。节名取交付物本身，不用方法词；一节只写一个交付物，尚未想清的节留空标题。

节内一行一条，祈使句或陈述句，必要时括注约束。**做完一节就删一节**：近景只有一份当前版，做完的留在上面，下一轮读的人会以为还要做；变更记进该仓的 `CHANGELOG`。

写不出先后顺序，说明方向还没收敛，退回 journal 再攒线索。

### intention

按主题分文件，主题集与同集 insight、roadmap 对齐。日志里没有内容的主题不建文件。一条一行：

```markdown
# 主题名

- **意图**：要 X，不要 Y。背景：摩擦或提问一句（YYYY-MM-DD）。
```

改写时守住四条：指令在日志里有原话；压缩时保留改变含义的约束（范围、数量、例外）；看似冲突的几条写清解耦条件；与 insight、roadmap 实质重复的不收。

## 语义界线

界线只写相邻两类之间，跨类的不写。

**journal 与 insight**：前者记事件，后者记机制。事件抽掉日期与当事人就没了；机制抽掉之后还在。

**insight 与 roadmap**：前者说世界怎么运转，后者说我去做什么。带「先做」「应该」「不做」的是选择，不是认识。两者并存时，认识留 insight，动作归 roadmap，各写一句。

**insight 与 profile**：前者是一句能被推翻的话，后者是一套反复出现的判断方式。一次事件就能证伪的进 insight；跨事稳定、改起来要动整个人的进 profile。

**insight 与 intention**：同一条内容，insight 写成能对错的机制，intention 写成给 AI 的指令。已经成了决策、指令不再多说什么的，以 roadmap 为准，intention 不重复收。

**roadmap 内部**：已决策要有行动跟着，没有行动的只能挂待决策。提议不等于决定。

**intention 与其余**：intention 收现场要求，原话优先，不做提炼。提炼过的就不是意图，是结论。

**规格与论文**：规格留定义与规则，论文留解释、例子与例外。同一内容两处展开，就是两份会各自过时的复制件。跨层只留互链。

**章程与规格**：章程管权责与执行，规格管对错标准。一条规定要人签字放行才生效的，是章程。

## 正反例

取自真实发生过的事，成对给出。

**例一，机制与事件**

- 收进 insight：初稿必冗余，因为遗漏可见、冗余不可见；把「生成后强制砍一轮」固化成默认一步，冗余就从每次判断变成固定动作。
- 留在 journal：今天让 AI 写东西，第一版又长又散，砍了一轮才好。

理由：后者去掉日期就空了。

**例二，认识与动作**

- 收进 insight：约束生成很难，约束验收容易；生成难控，检查好做。
- 收进 roadmap：先做存量巡检，用数出来的量决定闸门要不要装。

理由：前者描述落差，后者排先后。

**例三，可推翻与不可推翻**

- 不收：整个系统开始观察自己，形成自指闭环。

理由：推不翻，推翻之后也不改任何做法。这类话适合写进论文，不适合进 insight。

**例四，规格与论文**

- 只够进论文：治理成本的三项与净收益公式，写完被否决，降为论文里的一节。
- 够格进规格：语境由语场、语旨、语式三项构成，每项能分别求值。

理由：前一例给不出数据支撑的阈值，权重靠估；后一例定义稳定、边界清楚。

**例五，章程、规格与手册**

- 章程：新增禁用词须注明日期与出处，移出须写明用户改口的时间。
- 规格：同一条禁止项，写成「词不属于目标语境即为错配」。
- 手册：跑检查、看命中、按替代写法改，三步。

理由：章程管程序与责任，规格管对错，手册管步骤。

**例六，做完的那条**

- 近景只留未完成的：某节做完，从主题文件里删掉，变更记进 `CHANGELOG`。
- 不留在近景：做完的继续挂着，下一轮读的人会以为还要做。

理由：近景只有一份当前版，写完的那份就是历史。

## 自检

写完一处，逐条过：

1. 先问两域：这是陈述世界，还是规定做法。
2. 抽掉日期、人名、项目名，这句还成立吗？不成立，退回 journal。
3. 它回答「下一步干什么」吗？是，归 roadmap，再看有没有行动跟着。
4. 它讲的是「我反复怎么判断」吗？是，归 profile。
5. 它是「要 X 不要 Y」的原话吗？是，归 intention，原样收。
6. 后来的事能推翻它吗？推翻之后做法会变吗？两个都否，不收。
7. 要进规格，概念入体系了吗？阈值有出处吗？没有，先进论文。
8. 这一处已经有同一句了吗？有，就地改写或留互链，不另起一条。

## 常见误判

- 把推演当标准：没有数据支撑的阈值，只能进论文，等验证过再升格。
- 把提议写成已决策：说了「应该」，没有行动，仍是待决策。
- 把动作混进洞察：句子以「要」「应该」开头，先看它是否其实归 roadmap。
- 把单次事件拔高成机制：一次出错只说一次，同一机制反复出现才写进 insight。
- 把提炼过的结论当意图：意图收原话，提炼过的归 insight 或 roadmap。
- 写完不撤：近景只有一份当前版，做完的要从主题文件里删掉。
- 一类内容抄到多层：同一内容只在一处展开，其余留一句互链。
- 日志里没有的不编造：拿不准就不收，留在日志里等它重复。
